## 2026-09-30 · 冻结 Host Action v1 兼容协议契约
- 背景: 需要在多子项目协作体系下核对并锁定 Host Action v1 协议规范，确保配置层、传输层与状态广播层完全符合 EasyInput App 既有通信合同。
- 决定:
  1. **配置层**：保存完整的 `host_action:<canonical-lowercase-uuid>`。必须严格校验规范小写 UUID（`8-4-4-4-12`），非规范、大写或含非法字符直接拒绝（fail closed），不自动转小写。
  2. **共享载荷编码层**：固定使用 Report ID `0x11`、kind `0x05`、chunk index `0`、total chunks `1`、data length `36`。UUID ASCII（无前缀）写入载荷 `[4..39]`，余量 `[40..62]` 全部保持归零。
  3. **传输路由层**：按下发送一次，松开不发送；USB 与 BLE 使用相同报文内容并遵循既有单通道选择（USB 优先，失败不迁移至 BLE，绝对不双发）。
  4. **状态响应与能力声明**：`0x04` 继续专用于状态响应；能力对象声明 `"host_action_v1": true`；BLE 完整状态 JSON 严格保持在 512 字节以内。
- 四个语义层划分:
  1. 配置持久化层（NVS 校验与存储）
  2. 共享 payload 编码层（Report ID `0x11` / kind `0x05` 标准 63 字节容器）
  3. USB/BLE 传输路由层（单通道选择与生命周期锁定）
  4. 状态序列化层（`0x04` 状态与能力声明广播）
- 不承担范围 (Non-goals):
  1. 固件不保存、不解析应用名称、安装路径或 Bundle ID（映射关系仅由桌面应用维护）。
  2. 不新增额外的协议通道、编号或非标报文容器。
  3. 不更改硬件 GPIO、BOOT 下载逻辑、电源生命周期或存储分区。
  4. 不采用静默转小写、长度截断或双发机制来绕过合同规范。
